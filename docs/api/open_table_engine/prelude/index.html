Traits§

Command
Un Command es la intención de un jugador (“quiero tirar el dado”, “quiero jugar esta carta”). Es solo datos: nunca contiene lógica.
Component
Un Component contiene únicamente datos, nunca lógica (I1 del RFC: un Component nunca modifica otro Component).
Event
Un Event representa un hecho consumado (“se pagó el alquiler”, “se reveló esta carta”). Es inmutable y, como Command, se define como trait object serializable para que cada juego registre los suyos sin tocar el core.
Resource
Un Resource es estado global único dentro de la Session (el mazo, el tablero, las reglas activas). Igual que Component, se define acá solo como contrato mínimo; el mapeo real a bevy_ecs::Resource vive en open_table_engine.
Transport
Abstracción total de la red. open_table_core no sabe qué hay del otro lado: puede ser Nearby Connections en Android, MultipeerConnectivity en iOS, o un socket TCP en desktop para testing. Quien implementa este trait vive fuera de este crate (en el puente de Godot o en un mock de tests), nunca acá.
