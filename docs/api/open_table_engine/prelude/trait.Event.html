Expand description

Un Event representa un hecho consumado (“se pagó el alquiler”, “se reveló esta carta”). Es inmutable y, como Command, se define como trait object serializable para que cada juego registre los suyos sin tocar el core.

La diferencia clave respecto al Event del RFC original es el método visibility(): sin esto, cualquier juego con información oculta (casi todos los juegos de cartas) sería imposible de implementar sobre el core, porque todo evento llegaría a todos los clientes.

Required Methods§

fn as_any(&self) -> &(dyn Any + 'static)

Igual que en Command: permite hacer downcast a la struct concreta sin que open_table_core la conozca. #[derive(GameEvent)] de open_table_macros lo genera solo.

Provided Methods§

fn visibility(&self) -> Visibility

A quién le llega este evento. Por defecto público (Monopoly, Catan, ajedrez: casi todo es público). Un juego de cartas sobreescribe esto para las cartas de mano.
