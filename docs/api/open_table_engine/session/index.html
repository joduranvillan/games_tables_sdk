Session: el contenedor de una partida en curso.

Tres invariantes de seguridad/consistencia que este archivo hace cumplir:

  1. process_command es el único método que muta el World (I3 del RFC): no hay forma de tomar una referencia mutable al World desde afuera.
  2. El sender de un comando SIEMPRE viene de la capa de red (qué conexión trajo estos bytes), nunca de un campo dentro del propio comando. Si el comando declara un issuer() distinto del sender real, se rechaza. Esto es lo que impide que un cliente mande comandos “de parte de” otro jugador.
  3. Cada comando aceptado se guarda en un log ordenado por tick. Ese log alcanza para dos cosas sin necesitar serializar el World entero: reproducir la partida completa (replay) y, filtrando los eventos resultantes por Visibility, reconstruir lo que un cliente que se reconectó se perdió (resync).
