Expand description

Un Command es la intención de un jugador (“quiero tirar el dado”, “quiero jugar esta carta”). Es solo datos: nunca contiene lógica.

Se define como trait object serializable (#[typetag::serde]) en lugar de una enum cerrada a propósito: así, el crate de un juego nuevo (ej. chess_plugin) puede declarar sus propios comandos concretos sin que open_table_core necesite conocerlos ni recompilarse.

fn clone_box(&self) -> Box<dyn Command>

Clona el comando envuelto en un Box. Necesario para clonar Box<dyn Command>.

Source

fn as_any(&self) -> &dyn Any

Necesario para que el rule engine (en open_table_engine) pueda hacer downcast a la struct concreta sin que open_table_core la conozca. #[derive(GameCommand)] de open_table_macros lo genera solo.

Provided Methods§

Source

fn issuer(&self) -> Option<PlayerId>

Jugador que el propio comando DICE que lo emite. Esto es una afirmación del payload, no una verificación — por eso Session (en open_table_engine) exige que coincida con el sender real que vino de la conexión de red antes de ejecutar nada. Ver Session::process_command.
