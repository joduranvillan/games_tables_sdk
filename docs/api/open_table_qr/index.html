Código QR de invitación a una sala.

Una aclaración de diseño importante: Nearby Connections (Android) y MultipeerConnectivity (iOS) YA hacen descubrimiento de dispositivos cercanos solos - no hace falta ningún código para que un teléfono “encuentre” a otro. El QR acá resuelve un problema distinto: cuando hay más de una partida siendo anunciada cerca (dos mesas jugando en el mismo bar, por ejemplo), ¿a cuál se une el jugador? Y además, que un jugador no técnico no tenga que tipear nada.

Por eso el QR NO codifica direcciones de red, MACs de Bluetooth ni IDs de conexión de Nearby Connections/Multipeer - esos son manejados por esas APIs y son efímeros. El QR codifica solo un JoinPayload chico: un join_code legible (también se muestra como texto, por si alguien no puede escanear) que el cliente usa para filtrar, entre los dispositivos que ya descubrió por Bluetooth/Wi-Fi, cuál es el correcto.

Functions§

generate_join_code
Genera un código corto, legible, para mostrar junto al QR. Usa RandomService (el mismo que ya usa el motor para dados/barajado) en vez de una fuente de aleatoriedad nueva, para no introducir una segunda noción de “azar” en el SDK.
generate_join_qr_svg
Genera el QR como un string SVG, listo para que el bridge de Godot lo cargue como textura (Godot puede rasterizar SVG directamente, o este string se puede convertir a PNG del lado de Godot si hace falta).
parse_join_payload
El lado del cliente: decodifica lo que salió de escanear el QR (o de tipear el join_code a mano como fallback).
